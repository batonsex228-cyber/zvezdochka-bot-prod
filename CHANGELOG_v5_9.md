# v5.9.0 — BOOKING + FIRST-CONTACT UX

## Бронирования

- Добавлен отдельный booking-модуль для динамических заявок на беседку/корпус.
- Источник истины по занятости — Google Таблица через Google Apps Script Web App.
- Бот не угадывает доступность: слот проверяется только серверным booking API.
- Временный hold создаётся только после того, как известны услуга, дата/время и количество гостей; конкурирующие заявки защищаются `LockService` на стороне Google Apps Script.
- После ФИО, телефона и числа гостей родитель подтверждает заявку.
- Заявка получает статус `pending_manager` и блокирует слот до решения менеджера.
- Менеджеру приходит карточка во VK с кнопками «Подтвердить» / «Отклонить».
- После решения менеджера родитель автоматически получает результат в том же диалоге.
- Если календарь/Google API недоступен, бот ничего не обещает и передаёт запрос человеку.
- Временные booking-сессии хранятся в существующей SQLite runtime-базе и переживают перезапуск контейнера.

## Google Sheet bridge

В `google_apps_script/` добавлены:

- `Code.gs` — готовый Web App API;
- `SETUP_RU.md` — пошаговая настройка;
- автоматическое создание листов «Бронирования», «Объекты и услуги», «Блокировки», «Настройки»;
- строгая проверка пересечений, статусов, ограничений времени и длительности;
- секрет API хранится в Script Properties, а не в самой таблице.

Беседка и корпус добавляются как **выключенные** примеры. Никакие часы, вместимость или длительность не считаются правдой, пока менеджер не заполнит реальные правила и не включит нужную строку.

## First-contact UX

Исправлен важный сценарий: если новый родитель не нажимает Start и сразу пишет
`Добрый вечер, подскажите ...`, бот:

1. отправляет приветственное сообщение о том, кто он;
2. НЕ теряет исходный вопрос;
3. тем же входящим сообщением запускает FAQ / booking / human handoff;
4. вторым сообщением отвечает на вопрос или сообщает о передаче специалисту.

Повторять вопрос больше не нужно.

## Совместимость

- Google booking выключен по умолчанию (`BOOKINGS_ENABLED=false`). Пока он не настроен, v5.8-поведение динамических вопросов сохраняется: запрос идёт специалисту.
- Миграции SQLite только добавочные; существующие тикеты, аналитика, знания менеджера и подписки не удаляются.


## Pre-release hardening

- Запрещено создавать почасовой hold на время, которое уже прошло сегодня; та же защита дублируется в Google Apps Script.
- Google Таблица при `setupSpreadsheet()` принудительно переводится в `Europe/Samara` (UTC+4).
- Время открытия/закрытия корректно читается и как текст `10:00`, и как настоящее time-значение Google Sheets.
- Включённая, но неполностью заполненная услуга считается недоступной, а не «свободной без ограничений».
- Callback-кнопки родителей/менеджера защищены от устаревших и неизвестных действий.
- При запуске с включённым booking бот делает безопасный health-check Google API; сбой не роняет поддержку и оставляет handoff человеку.
- Добавлен `scripts/test_booking_connection.py` для живой проверки Google Web App без создания брони.
- Перед снятием `LockService` изменения таблицы принудительно `flush()`-ятся, чтобы конкурентный запрос видел уже записанный слот.
- Ошибка конфигурации Booking (URL/секрет/ID менеджера) больше не роняет основной VK-бот: модуль остаётся выключенным, а запросы идут по безопасному handoff.

- Исправлен пошаговый сценарий аренды корпуса: если дата начала и дата окончания приходят двумя сообщениями, второе сообщение теперь корректно записывается как дата окончания.
- Если родитель меняет дату/время/длительность/число гостей уже после временного hold, старый hold снимается и слот проверяется заново — сводка для родителя не может разойтись с фактической записью в Google.
- `submit_booking` повторно валидирует вместимость, блокировки и доступность непосредственно перед переводом hold в `pending_manager`; изменение правил менеджером между шагами приводит к безопасному отказу и новой проверке, а не к некорректной заявке.
