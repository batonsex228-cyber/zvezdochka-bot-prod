# Google Таблица бронирований — настройка для v5.9.0

Эта папка уже содержит готовый Google Apps Script. Никакой Google API key создавать не нужно: бот общается с Web App по HTTPS, а доступ защищён отдельным секретом.

## Что нужно сделать один раз

1. Создать новую Google Таблицу, например **«Звёздочка — бронирования»**.
2. В таблице открыть **Расширения → Apps Script**.
3. Полностью заменить содержимое `Code.gs` кодом из файла `google_apps_script/Code.gs`.
4. Сохранить проект и вручную запустить функцию `setupSpreadsheet()`.
5. Google попросит разрешение на работу с этой таблицей — подтвердить его владельцем таблицы.
6. Скрипт автоматически выставит для таблицы часовой пояс `Europe/Samara` (UTC+4), чтобы время менеджера совпадало со временем лагеря. В настройках проекта Apps Script также рекомендуется выбрать `Europe/Samara`.
7. В **Execution log / Журнал выполнения** появятся `SPREADSHEET_ID=...` и `BOOKING_API_SECRET=...`. Секрет нужно сохранить и никому не публиковать.
8. Проверить вкладку **«Объекты и услуги»**. И беседка, и корпус создаются **выключенными**, чтобы бот не начал принимать заявки по выдуманным ограничениям. Заполните реальные часы работы/режим, длительность, вместимость и только потом поставьте `enabled = TRUE` у нужной строки.
9. Выбрать **Deploy → New deployment → Web app**:
   - Execute as: **Me / владелец скрипта**;
   - Who has access: вариант, позволяющий боту обращаться к URL без входа в Google. Доступ к данным всё равно закрыт `BOOKING_API_SECRET`.
10. Скопировать URL, заканчивающийся на `/exec`.
11. На сервере бота добавить в `.env`:

```env
BOOKINGS_ENABLED=true
BOOKING_API_URL=https://script.google.com/macros/s/ВАШ_ID/exec
BOOKING_API_SECRET=ВАШ_СЕКРЕТ
BOOKING_TIMEZONE=Europe/Samara
BOOKING_HOLD_MINUTES=15
```

После изменения `.env` перезапустить контейнер.

## Листы

- **Бронирования** — единый журнал заявок бота и менеджеров.
- **Объекты и услуги** — какие услуги можно бронировать и их ограничения.
- **Блокировки** — ручное закрытие времени/дат (ремонт, мероприятие, санитарный день и т. п.).
- **Настройки** — технические значения.

## Важно

- Бот никогда не решает сам, свободна дата или нет: решение выдаёт только общий календарь Google Таблицы.
- При создании временной брони Apps Script использует `LockService`, поэтому два одновременных запроса не должны занять один и тот же слот.
- Статусы `hold`, `pending_manager` и `confirmed` блокируют интервал; `cancelled`, `rejected` и `expired` — нет.
- Не удаляйте строки бронирований вручную. Для истории лучше менять статус.

## Что менеджер увидит в таблице

Лист **«Бронирования»** — основной журнал. Даты и время выводятся в читаемом формате `дд.мм.гггг чч:мм`. Менеджер может фильтровать строки по статусу, услуге и дате.

Для ручной записи менеджер должен заполнить как минимум: `booking_id`, `status`, `service_key`, `resource_key`, `start_at`, `end_at`. Активные статусы `hold`, `pending_manager`, `confirmed` блокируют соответствующий интервал для бота. Лучше не удалять старые строки — менять статус, чтобы сохранялась история.

Если у одной услуги несколько объектов (например, несколько беседок), добавьте несколько строк с одинаковым `service_key`, но разными `resource_key`. Бот выберет подходящий свободный объект только после проверки времени и вместимости.


## Проверка перед включением бронирований

После того как URL и секрет добавлены в `.env`, но до реального использования выполните:

```bash
python scripts/test_booking_connection.py
```

Скрипт ничего не бронирует. Он только проверяет `health` и видимость настроенных услуг. После успешной проверки можно оставить `BOOKINGS_ENABLED=true` и перезапустить контейнер.

## Обновление до API v5.9.2 / бота v6.0.3

После замены `Code.gs` один раз запустите `setupSpreadsheet()` из редактора Apps Script.
Функция не удаляет существующие строки бронирований. Она:
- добавляет поля цены в техническую схему;
- добавляет официальные тарифы в пустые price-поля услуг;
- создаёт вкладку **«Бронирования — менеджер»** с русскими заголовками;
- оставляет техническую вкладку **«Бронирования»** для API без ручного переименования колонок.

После запуска `setupSpreadsheet()` обновите существующее Web App deployment через **Manage deployments → Edit → New version → Deploy**. URL `/exec` должен остаться прежним. `doGet()` после обновления возвращает версию `5.9.2`.
