# Подключение путёвок на смены в Google Sheets — v6.0.4

## Важно до включения

Данные относятся к детям. Проверьте у оператора ПД лагеря законное основание сбора/обработки, действующее согласие, доступ менеджеров, размещение базы, необходимость локализации персональных данных и трансграничной передачи. В v6.0.4 персональные данные хранятся в SQLite на сервере; для Google Sheets предусмотрена безопасная конфигурация без ПД. Разрешать передачу ФИО/ДР/телефона в Google можно **только после отдельного юридического согласования**.

**Не запускайте экспорт идентифицирующих данных в Google только потому, что есть техническая возможность.** Согласие в боте не заменяет выполнения остальных требований законодательства.

## Шаг 1 — обновите Google Apps Script

1. Откройте **существующий** Google Apps Script, обслуживающий бронирование беседок.
2. Сделайте резервную копию старого `Code.gs` (и Google-таблицы).
3. Замените `Code.gs` на код из каталога `google_apps_script/Code.gs` версии 6.0.4. **Не удаляйте Script Properties** `BOOKING_SHEET_ID`, `BOOKING_API_SECRET` и остальные действующие настройки.
4. Из редактора один раз запустите `setupSpreadsheet()` с действующими полномочиями: в прежней таблице появятся 5 вкладок «Смена 1»…«Смена 5». Аренда продолжит работать в старых вкладках.
5. Убедитесь, что все 5 вкладок появились, есть русские названия столбцов и фильтры.
6. В Apps Script: Deploy → Manage deployments → Edit существующее Web App deployment → New version → Deploy. Сохраните действующий URL `/exec`, если он сохранился.
7. Проверьте `BOOKING_API_URL` в серверном `.env`: это тот же рабочий `/exec` URL.

**Для безопасной конфигурации Script Property `SHIFT_PII_EXPORT_ALLOWED` оставьте `false`.** Тогда в Google будут время, номер заявки, номер смены, статус и ID менеджера/VK без ФИО, даты рождения и телефона. Если оператор ПД письменно разрешил именно такую передачу полных данных и обеспечил все необходимые требования, возможен отдельный **двойной** opt-in: Script Property `SHIFT_PII_EXPORT_ALLOWED=true` и `SHIFT_EXPORT_PII_TO_GOOGLE=true` в Docker `.env`.

## Шаг 2 — настройте Docker

В существующем файле `.env` добавьте (сохраните все прежние секреты, не перезаписывайте сам файл):

```dotenv
SHIFT_BOOKINGS_ENABLED=true
# Действующая HTTPS-страница именно лагеря с информацией об обработке ПД:
SHIFT_PRIVACY_POLICY_URL=https://<ОДОБРЕННЫЙ_АДРЕС_ОПЕРАТОРА>
# Настройка доступных смен; резервную пятую не открываем без подтверждения:
SHIFT_ACTIVE_NUMBERS=1,2,3
# Строго false до отдельной юридической проверки:
SHIFT_EXPORT_PII_TO_GOOGLE=false
```

Нужно, чтобы ранее были настроены `VK_MANAGER_USER_ID`, `BOOKING_API_URL` и `BOOKING_API_SECRET`. `BOOKINGS_ENABLED=true` требуется только для старой аренды; модуль заявок на смены может использовать тот же API независимо от флага аренды.

`SHIFT_PRIVACY_POLICY_URL` должен быть реальным адресом опубликованного документа, а не `https://<...>` из примера. Если его нет, модуль путёвок **корректно останется выключенным**, а остальные функции бота работают.

## Шаг 3 — GitHub → Docker

- Используйте полную сборку v6.0.4 или наложите архив патча строго поверх v6.0.3.
- Выполните `python scripts/self_test.py`, `node google_apps_script/self_test.js`, `python scripts/preflight.py`.
- Закоммитьте новые файлы и запустите ранее настроенный workflow GitHub Actions. Проверьте публикацию нового образа в GHCR.
- Сделайте **резервную копию рабочей SQLite базы** `runtime/bot.sqlite3` / volume ДО перезапуска контейнера.
- На Docker-сервере обновите образ привычным способом (обычно `docker compose pull && docker compose up -d`; для Dockerfile-сборки — по текущей инструкции проекта).
- Проверьте `docker compose logs --tail=100` и строку `Shift applications: ON`. Она подтверждает включение логики, но не подтверждает доступность Google.

## Шаг 4 — проверки перед запуском

Только на вымышленных данных:

1. Напишите боту VK «Хочу купить путёвку на первую смену». Бот должен **сначала** показать ссылку на политику обработки ПД и спросить согласие.
2. Откажитесь: анкета завершится, персональные данные не появятся.
3. Повторите и согласитесь; последовательно заполните четыре поля.
4. На экране проверки выберите «Исправить» — данные начнут собираться заново. Затем отправьте заявку.
5. Убедитесь, что клиент получил номер и ссылку на документы, менеджер VK — уведомление с кнопками.
6. В Google должна появиться ровно одна строка во вкладке «Смена 1». При безопасном режиме ФИО/ДР/телефон в этой строке должны остаться пустыми.
7. Менеджер нажимает «Подтвердить»; проверьте обновление статуса в Google и ответ родителю. Повторное нажатие не меняет состояние.
8. Протестируйте смены 2/3, попытку на неактивные смены 4/5, команду `#смены`, аренду беседки, FAQ, административные команды.
9. Временно отключите Google API на тесте, проверьте, что новая заявка остаётся в SQLite и позже доходит до таблицы без дублирования.
